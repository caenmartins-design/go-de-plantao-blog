PASSO 0 — Sincronizar o repositório antes de tudo:
  git fetch origin
  git status
Se houver mudanças locais não commitadas de trabalho alheio (ex: newsletter/entrega/inscritos.py ou qualquer outro arquivo que não seja seu), NÃO as descarte — faça 'git stash push -m "wip-automacao-nao-relacionado" -- <arquivo>' antes de prosseguir, e devolva com 'git stash pop' no final (Passo 6), depois de publicar. Se HEAD estiver atrás de origin/main sem commits locais próprios, faça 'git merge origin/main --ff-only' para sincronizar.

  python3 main.py buscar
Isso cria dados/artigos_brutos.json com artigos novos (não vistos em execuções anteriores — a lista de vistos já é rastreada em dados/vistos.json, versionado no git).
Se 'buscar' retornar poucos ou nenhum artigo novo (ex: <5), ainda assim prossiga com o que houver; se vier zero, pule para o PASSO 5 sem gerar newsletter nessa semana e relate isso no resumo final.

PASSO 3 — Gerar e publicar no blog:
  python3 main.py gerar
Isso gera o HTML da newsletter e tenta automaticamente fazer commit + push (adiciona um card em newsletters.html e o arquivo newsletters/{data}.html). Se o push automático falhar (ex: 'cannot rebase: You have unstaged changes' ou divergência do remoto), resolva manualmente: rode 'git fetch origin', verifique divergência real com 'git rev-list --left-right --count HEAD...origin/main' — se não houver commits novos no remoto ('0 0'), apenas prossiga direto para o commit; se houver, faça 'git merge origin/main --ff-only' (nunca rebase forçado, nunca --force push). Depois rode 'git add newsletters.html newsletters/{data}.html' + commit + 'git push origin main'. NÃO use 'git add -A' — adicione só esses dois arquivos específicos para não commitar nada além da newsletter.

PASSO 4 — Marcar artigos como vistos (evita repetição nas próximas semanas):
Depois que o PASSO 3 confirmar sucesso, rode:

Depois, faça commit + push SÓ do arquivo newsletter/dados/vistos.json (ele é rastreado propositalmente, apesar do resto de dados/ ser ignorado pelo git):
